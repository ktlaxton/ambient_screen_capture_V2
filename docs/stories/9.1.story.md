# Story 9.1: Offline License Key System

## Status
Done — implemented + unit-tested 2026-06-13.

## Story
**As the** owner shipping a paid product,
**I want** license keys that activate Premium entirely offline,
**so that** I never run (or pay for, or get hacked through) a license server, and customers can
activate with no account and no internet.

## Acceptance Criteria
1. **Signed keys, embedded public key.** Keys are signed by a private ECDSA P-256 key the owner
   holds; the app verifies against an embedded public key. A key minted by any other key fails.
2. **Tamper/format safety.** A tampered payload, wrong-key signature, malformed/garbage string,
   or unknown edition all fail with a clear message and **never throw**. No key = free edition
   (a normal state, not an error).
3. **Expiry support.** A key may carry an optional expiry date; past it, the key is rejected with
   the date. Perpetual keys (no expiry) are the default.
4. **Service + persistence.** `ILicenseService` holds the current entitlement; the key string
   persists in `ApplicationSettings.LicenseKey` and is validated on every launch before any gated
   feature starts.
5. **One format implementation.** The mint and verify code share one format definition so the
   owner's tooling (Story 9.3) and the app can never drift.
6. **Tests.** xUnit covers valid/tampered/foreign/expired/garbage keys and the service lifecycle.

## Implementation
- `src/Engine/Licensing/LicenseValidator.cs` — pure verify; `AFX1.<b64url(payload)>.<b64url(sig)>`,
  ECDSA-P256/SHA-256, embedded `ProductionPublicKey`. Returns a `LicenseInfo` (never throws).
- `LicenseMinter.cs` — shared signing (used by tests with ephemeral keys; the owner's PS tool
  uses the same format with the production key).
- `ILicenseService` / `LicenseService` — DI singleton; `Apply(key)` adopts a valid (or empty) key,
  leaves the entitlement untouched on an invalid key.
- `ApplicationSettings.LicenseKey` (+ normalization default), applied in `EngineCoordinator.StartAsync`.

## QA Results
xUnit green (367 total). Real-key round-trip proven via `tools/license/new-license.ps1`, which
self-verifies each minted key against the same embedded public key the app uses.

**Adversarial review (2026-06-13)** — a multi-agent review (4 dimensions × 2-skeptic verify,
21 candidates → 6 confirmed) hardened this story:
- **Clock-rollback on dated keys** (confirmed high) → added a monotonic clock floor in
  `LicenseService` (`%AppData%\AmbientFx\.license-clock`); expiry is judged against
  `max(today, highest-date-seen)`. Validator clock is now injectable (`Validate(key, pub, nowUtc)`)
  for testability. Residual local-admin limit documented in `docs/MONETIZATION.md`.
- **Unbounded key length** (confirmed) → `MaxKeyLength` cap before any allocation.
- **Expiry boundary untested** (confirmed) → test: a key expiring today is valid through the day.
- New `LicenseServiceTests` cover the floor (future-floor rejects an earlier-expiring key,
  never moves backward, corrupt file is non-fatal) using an ephemeral keypair (no CI secret).
Dismissed (correctly, by the skeptics): "settings.json edit unlocks premium" and "web gating is
UX-only" — the engine is the enforcement boundary, so neither is a real bypass.
