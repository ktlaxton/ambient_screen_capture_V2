# Story 8.2: Per-Device Placement & Tuning UI

## Status
Done — implemented, tested, and owner-verified on hardware 2026-06-12.

## Depends on
8.1 (the device service, auto-mapping, and the read-only device list must exist first).

## Story
**As a** user whose peripherals aren't laid out the way the auto-mapping assumes,
**I want** to tell the app where each device physically sits relative to my screen and tune its
brightness/enablement,
**so that** the ambient colors land correctly — my left-of-keyboard light strip glows with the
screen's left edge even though iCUE has no idea where it is on my desk.

## Context
Story 8.1 ships **automatic** position mapping: each device's LED `(x,y)` positions (normalized
per device) are projected onto the screen-edge zones. That's correct for devices whose internal
LED geometry matches their desk placement, but iCUE can't know that a light strip is mounted to the
*left* of the monitor vs behind it, or that the keyboard sits below-center. This story adds a
manual placement layer on top of the auto-mapping, plus per-device brightness/enable, and folds it
all into the preset system so a saved look restores the device setup too.

## Acceptance Criteria
1. **Per-device placement.** For each discovered device the user can set where it sits relative to
   the screen — at minimum a coarse anchor (left / right / above / below / behind / surround) and,
   for strips, an orientation/flip so the zone order runs the right way. This overrides 8.1's
   automatic mapping for that device; "Auto" remains the default and is always available.
2. **Per-device brightness + enable.** Each device has its own brightness multiplier (on top of the
   global peripheral brightness from 8.1) and an include/exclude toggle, so the user can dim or drop
   a single device without disabling the whole feature.
3. **Live preview/feedback.** Changing a device's placement applies live (no restart) and is
   visible on the hardware immediately; the UI reflects the current mapping clearly (e.g. a small
   per-device indicator of which screen edge feeds it).
4. **Persistence keyed by stable device identity.** Per-device settings persist across restarts and
   reconnects, keyed by a **stable device identifier** (model + serial / RGB.NET device id — not a
   volatile enumeration index), so unplugging and replugging, or starting iCUE later, restores the
   right config. Unknown/new devices fall back to Auto.
5. **Presets carry device config.** Per-device placement/brightness/enable is included in the
   `Preset` snapshot (Story 7.2) so saving and loading a preset restores the peripheral setup, with
   the same "don't clobber hardware that isn't present" grace `LoadPreset` already applies to
   monitor selection.
6. **Bridge contract.** The new per-device settings structure is added to `ApplicationSettings`,
   mirrored in `web/src/shared/bridge.ts`, and is forward/back compatible (unknown keys ignored,
   missing keys default — Story 7.2/SettingsService pattern).
7. **Tests green & extended.** xUnit covers the placement-override projection (each anchor/flip
   produces the expected edge→LED feed) and the stable-identity persistence/merge logic. Vitest
   covers the per-device UI controls and their live-apply path. Existing suites stay green.
8. **Real-hardware verification.** Owner-verified: set a strip to "left", confirm it follows the
   screen's left edge; dim one device; exclude one device; save/load a preset and confirm the device
   setup restores. (Recorded in QA Results.)

## Dev Notes

### Build on 8.1's pure projection helper
[Source: Story 8.1 `AmbientFx.Devices.LedProjection`]
- 8.1 maps normalized LED `(x,y)` → edge zones automatically. This story makes the mapping take a
  `DevicePlacement` so the *device-as-a-whole* is positioned relative to the screen before its LEDs
  are projected. Keep the helper pure (no RGB.NET types) so the anchor/flip math is unit-tested
  without hardware — the same discipline as `MonitorLayoutTests` and Story 7.5's
  `monitorProjection.test.ts`.

### Stable identity is the subtle part
- RGB.NET enumeration order and indices are **not** stable across reconnects/iCUE restarts. Persist
  per-device config under a stable key (model + serial, or RGB.NET's device id if it's stable) and
  merge on discovery. New/unknown devices → Auto. Test the reconnect/replug merge explicitly.

### Preset integration
[Source: `src/Engine/Models/ApplicationSettings.cs` (`Preset`/`Snapshot`), `EngineCoordinator.LoadPreset` (Story 7.2)]
- `Preset.Snapshot` is a full settings clone with empty `Presets`. Device config rides along
  naturally once it's an `ApplicationSettings` field. On load, do the same "preserve what's physically
  present, restyle the rest" grace that 7.2 added for monitor source/target selection.

### Scope
- Still **auto-discovery** of devices (from 8.1); this story is about *placement*, not adding
  vendors (8.3) or installer/licensing (8.4).
- A full drag-on-a-canvas desk layout editor is **not** required — a coarse anchor + flip is enough
  for correct mapping. A richer spatial editor could be a later enhancement if the owner wants it.

### Testing
- xUnit for placement projection + identity/preset merge (no hardware). Vitest for the UI.
- Owner manual pass for the on-hardware placement feel (AC8).

### Completion Notes List
- **Stable identity (AC4):** `CorsairRGBDeviceInfo.DeviceId` is the iCUE SDK's unique device
  id and survives replug/reconnect/iCUE restarts — used as `corsair:<id>`. Non-Corsair (8.3)
  devices fall back to `Manufacturer:Type:Name` with a deterministic `#n` dedupe suffix.
  **Breaking note vs 8.1:** device ids changed format from the volatile `index:name` to the
  stable key; nothing persisted the old ids, so no migration needed.
- **Anchor semantics:** left/right/above/below = "the device listens to that one screen edge,
  indexed by the LED's position along the edge's axis" (the LED's other coordinate is
  deliberately ignored). `surround` maps each LED's angle around the device center onto the
  screen perimeter clockwise from the top-edge midpoint — built for fan rings. `behind` is an
  explicit alias of the nearest-edge auto behavior (bias-light style). Flip mirrors the
  direction where one exists; for auto/behind it's ignored rather than guessed.
- **Excluded devices go dark** (brightness 0) instead of being skipped — skipping would
  freeze them on their last pushed color, which reads as a bug on the desk.
- **Settings hygiene:** placements at full defaults are pruned on write (toggling a device
  back to Auto leaves settings.json clean); the map is bounded at 128 entries in both the
  command handler and load normalization.
- Coordinator passes the service a **cloned** placement snapshot under its gate, so the
  30 Hz timer thread never reads objects a UI command is mutating.
