# Story 9.2: Feature Gating & Premium UI

## Status
Done — implemented + tested 2026-06-13.

## Depends on
9.1 (the license service + entitlement).

## Story
**As a** free user,
**I want** a genuinely useful app that clearly shows what Premium adds and lets me unlock it,
**so that** I get value for free and can upgrade in two clicks — and **as the owner**, I want
the gates enforced where they can't be bypassed.

## Acceptance Criteria
1. **Engine-enforced gates.** Free tier = 1 target monitor, the four core effects, no per-monitor
   effects, no RGB peripherals. Every gate is enforced in `EngineCoordinator` (the web cannot
   bypass it): extra monitors stay listed but dormant, premium effects fall back to edge-glow,
   per-monitor overrides are ignored, RGB peripherals refuse to start.
2. **Graceful downgrade.** When premium settings exist but the license is absent/expired,
   settings are preserved (re-upgrade restores them) — never wiped or crashed.
3. **UX gating mirror.** The UI shows lock badges on premium effects, a Premium pill on dormant
   target monitors, a locked RGB-peripherals panel, and hides per-monitor effect selectors —
   driven by `premium.ts`, the mirror of `Entitlements.cs`.
4. **License panel.** A card shows the current edition; free shows perks + Upgrade button +
   key-entry/Activate; premium shows licensed-to + Remove. Activation is non-optimistic (engine
   validates and pushes back the real entitlement).
5. **External links.** The Upgrade link opens in the user's real browser, not an in-app popup.
6. **Live re-evaluation.** Activating/removing a key re-applies window count, effect fallbacks,
   and the RGB gate immediately (no restart).
7. **Tests.** xUnit covers every gate + the activate/deactivate/startup paths; Vitest covers the
   policy mirror, store license state, and the glue helper. Existing suites stay green.

## Implementation
- **Engine:** `Entitlements.cs` (policy); enforcement in `EngineCoordinator` —
  `BuildSpecs` (monitor cap), `EffectiveEffectId` (effect/per-monitor fallback), `ApplyEnabledState`
  (RGB gate), and command handlers for `setEffect`/`setTargetMonitors`/`setDevices` (reject +
  upsell toast) and `setLicenseKey` (activate/deactivate + re-apply). `ConfigPayload.License`
  carries entitlement to the UI.
- **Host:** `ControlWindow.OnNewWindowRequested` routes http(s) `target=_blank`/`window.open` to
  the OS browser (AC5); non-http requests are blocked.
- **Web:** `premium.ts` (mirror + `usePremium`), `store.license`, `bridgeGlue.setLicenseKey`,
  `LicensePanel`, lock UX in `EffectGallery` / `MonitorMap` / `DevicesPanel`. Simulator treats any
  non-empty key as premium (`?premium=1`) so the gated UI is demoable in a browser.

## Dev Agent Record
**Model:** Opus 4.8 (1M).
**Notes:**
- **Defense posture:** the web mirror is UX-only and explicitly documented as such; the engine is
  the enforcement boundary. A user editing `premium.ts` or the bundle still can't unlock features.
- Three new gating tests initially failed on `LastConfig` (startup posts no `PostToAll` config —
  the web requests state on boot); fixed by exercising the real `requestState` path via a new
  `LastControlConfig` harness helper, not by changing production behavior.
- The coordinator test harness defaults to **premium** so the large pre-Epic-9 suite exercises
  full behavior unchanged; `UseFreeEdition()` opts specific tests into the free tier.

## QA Results
367 xUnit + 281 Vitest green. Manual verification (owner): build the engine after any web change
(`dotnet build`) so the exe serves the new UI; toggle `?premium=1` in the simulator to preview
both tiers. On-hardware free/premium switch pass recommended before go-live (9.4).

**Adversarial review (2026-06-13)** confirmed the engine is the true enforcement boundary
(settings-edit and DevTools bypasses were raised and dismissed because the engine re-checks). It
found the **simulator** didn't mirror the engine's gates (premium effect / RGB-enable /
multi-monitor), which would mislead browser-based dev testing — now fixed in `simulator.ts` and
covered by new tests. Note: the multi-monitor fix *emits the upsell but keeps the full selection*
(matching the engine — dormant targets show a Premium badge), rather than truncating as first
suggested, which would have broken that UX.
