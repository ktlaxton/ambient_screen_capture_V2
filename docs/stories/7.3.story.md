# Story 7.3: Reliable Shutdown & Taskbar Quit

## Status
Ready for Review

## Story
**As a** user who wants to fully close the app from the taskbar,
**I want** closing the window (or right-click → Close from the taskbar) to actually quit the
program — and to be sure nothing keeps running in the background,
**so that** I'm never left with a ghost process I have to hunt down in Task Manager.

## Background / problem
The control window **does** show in the taskbar (`ShowInTaskbar = true`), but its `OnClosing`
handler **cancels the close and hides the window to the tray** — so "closing from the taskbar"
makes the window vanish while the process keeps running. WPF `ShutdownMode` is **not set
explicitly**, and the process only exits via an explicit `Application.Current.Shutdown()` triggered
by the tray's Exit item. The owner's two pains: (a) no obvious way to truly quit from the taskbar,
and (b) wanting certainty that quitting kills the whole process — engine, effect windows, tray,
background activation listener — with no leftover.

## Acceptance Criteria
1. Closing the control window from the taskbar (right-click → Close, or the window's X / Alt+F4)
   results in a **clear, intentional outcome**: either it **quits the app**, or it offers a
   first-time choice **"Minimize to tray"** vs **"Quit"** with a "remember my choice" option that
   is persisted in settings. (Default recommendation: show the choice once, remember it.)
2. There is always a **discoverable, reliable Quit**: the tray **Exit** item and an in-app **Quit**
   action both fully terminate the process.
3. After Quit, **no AmbientFx process remains**: the engine pipeline is stopped, **all effect
   windows are closed**, the tray icon is removed, the single-instance mutex is released, the
   background **activation-listener task/EventWaitHandle is signaled and torn down**, logs are
   flushed, and the process exits cleanly (verified: process is gone from Task Manager).
4. `ShutdownMode` is set **explicitly** to `OnExplicitShutdown` so window-hide behavior can't
   accidentally exit the app early, and an explicit `Shutdown()` reliably ends it.
5. Effect windows remain **out of the taskbar and Alt+Tab** (`ShowInTaskbar = false`,
   tool-window styles) — only the control window owns the taskbar presence. Quitting closes them
   regardless of state.
6. If the user chose "minimize to tray," that still works exactly as today (hide, restore via tray
   / second-instance activation) — this story doesn't remove the tray-first option, it makes Quit
   real and reachable.
7. Quit is **idempotent and race-safe**: invoking it from tray + window close at the same time
   doesn't double-dispose or hang (the existing `_exiting` / shutdown re-entrance guards hold).

## Dev Notes

### Where the friction lives
[Source: `src/Engine/Hosting/ControlWindow.cs`]
- `ShowInTaskbar = true` (~line 59); `WindowStyle = None` with custom chrome (~line 54).
- `OnClosing` (~lines 156-162) **cancels** unless `_forceClosing` is set, raising `CloseRequested`
  (hide-to-tray). `ForceClose()` (~lines 148-152) sets the flag for real shutdown.
- `ShowAndActivate()` (~lines 137-145) restores from minimized (used by tray + second-instance).

### App lifecycle
[Source: `src/Engine/App.xaml.cs:22-109,206-229`]
- `ShutdownMode` **not set** — set it to `OnExplicitShutdown`.
- Single-instance mutex `AmbientFx_SingleInstance_B6E3` + EventWaitHandle `AmbientFx_Activate_B6E3`.
- A background task waits on the activation event (~lines 206-229) and calls
  `ActivateControlWindowAsync()`; `OnExit` already sets `_activateEvent` and guards with `_exiting`
  (~line 80). Verify nothing here is a foreground thread that outlives `Shutdown()`.
- `OnExit` (~lines 78-109): `ShutdownAsync().GetAwaiter().GetResult()` → dispose DI → release mutex
  (UI thread) → flush logs.

### Teardown sequence to rely on
[Source: `src/Engine/Services/EngineCoordinator.cs:148-192`]
- Re-entrance guarded (`Interlocked`), cancels debounce save + flushes, stops monitor detection,
  `StopPipeline()`, **syncs effect windows to empty array (closes all effect windows)**, disposes
  window manager (closes control window), disposes tray, disposes save timer, final settings flush.

### Tray Exit wiring
[Source: `src/Engine/Services/SystemTrayService.cs`, `EngineCoordinator.cs:~109`]
- Tray "Exit" → `ExitRequested` → coordinator → `Application.Current.Shutdown()`. Route the new
  in-app Quit through the same handler so there's one shutdown path.

### Effect windows (leave their taskbar behavior as-is)
[Source: `src/Engine/Hosting/EffectWindow.cs:48-53,169`]
- `ShowInTaskbar = false`, `Topmost = true`, `ShowActivated = false`, `WS_EX_TOOLWINDOW |
  WS_EX_NOACTIVATE` — correct; they must close on quit but never own taskbar/Alt+Tab presence.

### New settings field
- Add `CloseAction` (enum: `Ask` | `Quit` | `MinimizeToTray`, default `Ask`) to
  `ApplicationSettings` and mirror on the bridge (`web/src/shared/bridge.ts`) per the versioned-
  contract rule. Persisted via `SettingsService` (camelCase JSON, atomic write).

### Testing
- xUnit for shutdown idempotency + teardown assertions (mock window manager / tray). Manual
  verification on the 3-monitor rig per AC.
