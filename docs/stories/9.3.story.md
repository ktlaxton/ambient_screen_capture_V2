# Story 9.3: Fulfillment & Storefront

## Status
Done (tooling + docs) 2026-06-13 — owner wires the storefront account when ready to sell.

## Story
**As the** owner,
**I want** a buy → key-delivery pipeline that handles tax and works while I sleep,
**so that** a purchase produces a working Premium key with no manual step on my part.

## Acceptance Criteria
1. **Minting tool.** A script mints a valid key from the private signing key, with name/email/id
   and optional expiry, and self-verifies against the app's public key before printing.
2. **Merchant of record.** Checkout goes through Paddle or Lemon Squeezy so VAT/sales tax,
   invoicing, and refunds are handled for an individual seller (not a raw Stripe integration).
3. **Automated delivery.** A documented webhook flow: store fires "order paid" → server mints a
   key (tool/logic from AC1) → emails it / shows it on the receipt.
4. **Key handling.** The private key never touches the repo or the client; secrecy, backup, and
   rotation consequences are documented.
5. **Docs.** `docs/MONETIZATION.md` captures the storefront choice, the webhook contract, the
   refund/deactivation policy, and how it all ties to the offline key system.

## Implementation
- `tools/license/new-license.ps1` — mints `AFX1.…` keys (ECDSA-P256/SHA-256, base64url) from
  `~\.ambientfx-dev\license-signing.pem`, re-verifying every key against the embedded public key
  so a printed key is guaranteed to activate. Parameters: `-Name -Email -Id -ExpiresUtc`.
- `docs/MONETIZATION.md` — storefront comparison (Paddle vs Lemon Squeezy), the webhook→mint→email
  fulfillment flow with a Node sketch, key-secrecy/backup/rotation rules, refund/deactivation
  posture, and pricing guidance. Links the offline-key model from 9.1.
