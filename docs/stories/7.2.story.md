# Story 7.2: Richer Effect Controls & Palettes

## Status
Ready for Review

## Story
**As a** user tuning my ambient effects,
**I want** deeper, more expressive controls — color palettes, blend modes, and finer sliders — on
every effect,
**so that** I can dial in exactly the look I want instead of being stuck with a couple of knobs.

## Acceptance Criteria
1. The declarative `ParamDef` control system is extended with at least two new control types:
   - `color` — a single color picker (returns a hex string).
   - `palette` — a named gradient/palette chooser (e.g. Warm, Cool, Neon, Mono, Screen-reactive).
   (A `palette` could be modeled as a `select` of named palettes if a custom picker is too costly;
   the dev may choose, but the user-visible outcome — pick a palette per effect — must hold.)
2. The control window auto-renders the new control types from `ParamDef` the same way it does
   `range`/`select`/`toggle` today — no per-effect UI code.
3. The 5 existing effects (`edge-glow`, `plasma`, `audio-bars`, `particles`, `aurora`) are
   retrofitted with a richer, consistent param set where applicable: **palette/color source**,
   **blend mode** (normal/additive/screen), **speed**, **density/scale**, **glow/bloom**, and a
   **color source toggle** (screen-reactive vs fixed palette).
4. A small library of **shared param helpers** (e.g. standard palette definitions, a blend-mode
   enum→three.js mapping) lives under `web/src/effects/shared/` (or `web/src/shared/`) so effects
   reuse them instead of redefining.
5. New/changed params persist per-effect (round-tripped through `EffectParams` /
   `ApplicationSettings.EffectParamsById`) and apply **live** (no restart), matching today's
   "Changes apply live" behavior.
6. The **default preset set shipped with the app is expanded** (e.g. a few curated looks per
   effect) so users have good starting points out of the box.
7. The registry/manifest param-hygiene test passes with the new control types (extend it to
   validate `color`/`palette` defaults). `Reset to defaults` still works per effect.
8. The bridge contract change (new `ParamDef` types) is mirrored on the C# side; settings written
   by the new build load cleanly, and settings written by the old build still load (forward/back
   compatible — unknown params ignored, missing params fall back to defaults).

## Dev Notes

### What you're extending
[Source: `web/src/effects/types.ts:14-25`]
- `ParamDef` today: `{ key, label, type: 'range'|'select'|'toggle', min?, max?, step?, options?, default }`.
- The control UI auto-generates from these — so adding a type means: (a) add to the union,
  (b) teach `EffectParams.tsx` to render it. Nothing else is hardcoded per effect.

### Control UI renderer
[Source: `web/src/control/components/EffectParams.tsx:21-129`]
- `ParamRow` switches on `ParamDef.type` to render the control; `formatRange` shows 0–1 as %.
- "Changes apply live" + "Reset to defaults" (`resetEffectParams(module.id)`) already exist — the
  new types must slot into both.

### Params are opaque to the engine (good news for compatibility)
[Source: `web/src/shared/bridge.ts:53`, `src/Engine/Models/ApplicationSettings.cs:27`]
- `EffectParams = Record<string, number|string|boolean>`; C# stores them as
  `EffectParamsById: Dictionary<string, Dictionary<string, JsonElement>>` — opaque, round-tripped,
  never interpreted. A hex color string therefore persists with **no C# logic change**; just verify
  JSON (camelCase, `BridgeJson` options) serializes/deserializes strings cleanly.

### Presets
[Source: `src/Engine/Models/ApplicationSettings.cs:32-49`, `web/src/control/components/PresetsPanel.tsx`]
- `Preset` = `{ name, snapshot }` where snapshot is a full settings clone with empty `Presets`.
- Default/shipped presets should be seeded on first run (`FirstRunCompleted` flag exists). Confirm
  where first-run seeding happens (EngineCoordinator/SettingsService) and add curated presets there.

### Settings persistence
[Source: `src/Engine/Services/SettingsService.cs:15-99`]
- `%AppData%\AmbientFx\settings.json`, atomic write with `.backup.json`, camelCase, case-insensitive
  reads. Back-compat: unknown keys ignored on read, missing keys → model defaults.

### Coordination with Story 7.1
If 7.1 is in flight, land 7.2's shared palette/blend helpers first so new effects consume them.
The registry param-hygiene test is shared — coordinate the expected-count and type changes.

### Testing
- Vitest for `web/` (types, renderer, registry hygiene). xUnit for C# settings round-trip.
