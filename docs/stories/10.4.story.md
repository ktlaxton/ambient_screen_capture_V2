# Story 10.4: RGB Peripherals & Audio in the Simulator

## Status
Ready for Review

## Story
**As a** developer/QA,
**I want** virtual RGB peripherals and audio reactivity driven by the **real** engine across the
fabricated virtual layout, hardware-free and sound-free,
**so that** position-mapped LED output (per-device anchor/flip/brightness) and audio-reactive
behavior — for both on-screen effects and peripheral modulation — are verifiable on any monitor
topology without Corsair hardware or system audio.

## Context
Epic 8 made AmbientFx a desk-wide Ambilight: `RgbNetAmbientDeviceService` projects the same
`FramePayload.Edges` the effect windows get onto physical LED positions (Story 8.1), per-device
`DevicePlacement` anchors decide *where* each device reads the screen (Story 8.2), and an audio
layer modulates peripheral brightness (Story 8.3 AC4). All of that runs only against the owner's
Corsair hardware with iCUE up — it cannot be seen or regression-tested on a developer box, and the
projection's behavior across anchors/topologies is invisible without the physical devices in hand.

This story plugs RGB + audio into the Layout Simulator harness. Stories 10.1 (simulated topology +
capture) and 10.2 (composite window) already run the real `EngineCoordinator` against a fabricated
desktop and composite every virtual monitor's effect into one window. This story adds the **fourth
and fifth** of the four validation targets — RGB peripheral placement and audio-reactive behavior —
by swapping two more DI seams for simulated implementations, **without forking** any projection,
LED, or audio logic:

- A `VisualizationBackend : IRgbDeviceBackend` replaces the real `RgbNetBackend` factory and records
  the per-device per-LED sRGB colors the **real** `LedProjection` produces, so virtual peripherals
  can be drawn around the virtual layout with live colors.
- A `SimulatedAudioCaptureService : IAudioCaptureService` replaces WASAPI loopback and emits
  synthetic bands/intensity on the real cadence, so the real audio path (`DataProcessingService`
  shaping, audio-reactive effects, and `AudioModulation` peripheral brightness) all run.
- Because RGB peripherals are a **Premium** feature (Epic 9), the simulator activates a sim-Premium
  entitlement so the gated code path (`Entitlements.RgbPeripherals`) is actually exercised — mirroring
  how the browser simulator grants Premium via `?premium=1`.

The fidelity invariant from the epic holds: the simulator reuses `RgbNetAmbientDeviceService`,
`LedProjection`, `AudioModulation`, and the engine's audio consumer **unmodified**. The only
adaptation is *visualization* — recording `Apply()` colors and drawing them — never recomputing them.

## Acceptance Criteria

1. **VisualizationBackend taps the real LED colors.** A `VisualizationBackend : IRgbDeviceBackend`
   (dev-only) is injected via the existing backend factory seam in place of `RgbNetBackend`. Its
   `Connect()` returns the **simulated device set** (keyboard ~108 LEDs, mouse ~4, light strip ~27,
   mirroring `simulator.ts` `SIM_DEVICES`) with `NormalizedLeds` in 0..1 device space; its `Apply()`
   records the latest `IReadOnlyList<RgbDeviceColors>` (per-device `int[][]` sRGB 0-255) — produced
   by the **real** `RgbNetAmbientDeviceService` push timer running the **real** `LedProjection`. No
   projection or color math is reimplemented in the simulator; the backend only records what the
   service computed. Recording is thread-safe (the service's push timer fires on the threadpool).

2. **Virtual peripherals rendered per `DevicePlacement` anchor with live colors.** Each simulated
   device is drawn around the virtual layout in the 10.2 composite window, positioned per its
   `DevicePlacement.Anchor` (`auto`/`left`/`right`/`above`/`below`/`behind`/`surround`) relative to
   the source virtual monitor, with each LED filled from the recorded `Apply()` color and refreshed
   at the push cadence. Changing a device's `Anchor`, `Flip`, `Brightness`, or `Enabled` is visually
   reflected (e.g. a flipped strip reverses its color run; a disabled device goes dark; `surround`
   wraps the perimeter) so the placement behavior is verifiable across topologies — exactly the thing
   that is invisible without hardware.

3. **SimulatedAudioCaptureService drives the real audio path.** A
   `SimulatedAudioCaptureService : IAudioCaptureService` (dev-only) is injected in place of
   `AudioCaptureService` and emits `AudioAnalyzed` events with `Bands` (length == `BandCount`, each
   0..1, log-spaced low→high) and `Intensity` (0..1) and a monotonic `TimestampMs`, on the real
   ~30–60 Hz cadence, honoring `Start`/`Stop`/`IsCapturing`/`BandCount` and never throwing (NFR5).
   It does **not** touch WASAPI. The signal is selectable: a **124 bpm "track"** (the `makeSimFrame`
   kick+melody+sparkle pattern ported to C#), a **sine sweep**, and an optional **file-driven**
   source. The output flows through the unmodified `DataProcessingService.OnAudioAnalyzed` → `Shape`
   path so it appears in `FramePayload.Audio` and drives both audio-reactive effects and (via
   `AudioModulation.BrightnessFactor`) peripheral brightness modulation.

4. **Sim-Premium entitlement exercises the gated RGB path.** Because `Entitlements.RgbPeripherals`
   gates RGB peripherals behind Premium (Epic 9), the simulator activates a sim-Premium entitlement
   so `EngineCoordinator.ApplyAmbientDeviceState` actually starts the device service (and audio-
   reactive peripheral state applies). This mirrors the browser simulator's `?premium=1` Premium
   grant. The real `Entitlements`/`ILicenseService` gate is left **unmodified**; only the entitlement
   *state* the simulator runs under is sim-Premium. Free/Premium licensing and the signed build are
   unaffected (this code is behind `SIMULATOR_ENABLED` + the runtime gate from 10.1).

5. **Fidelity invariant: no forking.** `RgbNetAmbientDeviceService`, `LedProjection`,
   `AudioModulation`, the `IRgbDeviceBackend` contract, and `DataProcessingService`'s audio consumer
   run **unchanged**. The simulator only substitutes the backend (`IRgbDeviceBackend`) and the audio
   source (`IAudioCaptureService`) at the existing DI seams and *records*/*renders* their output. No
   bridge-contract change.

6. **Dev/QA-only, zero ship impact.** All code in this story sits behind `#if SIMULATOR_ENABLED`
   (Debug-config define) + the runtime `--simulator` / `AMBIENTFX_SIMULATOR` gate from 10.1, is
   compiled **out** of the signed Velopack/Release build, and has zero effect on Free/Premium
   licensing or packaging.

7. **Tests green & extended.** xUnit covers: `VisualizationBackend` records the correct per-LED
   sRGB colors for known frames/placements (drive the real `RgbNetAmbientDeviceService` with a known
   `FramePayload` + `DevicePlacement` and assert recorded `Apply()` colors match `LedProjection`
   directly); `SimulatedAudioCaptureService` cadence (≈30–60 Hz over a window) and range (bands &
   intensity in 0..1, `Bands.Length == BandCount`); and `LedProjection`/`AudioModulation` behavior on
   the synthetic inputs the simulator feeds (smoke that the ported 124 bpm pattern stays in range).
   Existing xUnit + Vitest suites stay green.

## Dev Notes

### Fidelity invariant (state it plainly)
The simulator MUST reuse the real pipeline unmodified — `EngineCoordinator`,
`MonitorLayout.ComputeRelation`, `monitorProjection.ts`, the effect runtime,
`RgbNetAmbientDeviceService`, `LedProjection`, `AudioModulation` — with **no fork** of the
projection/effect/LED/audio logic and **no bridge-contract change**. For this story the only
adaptations allowed are (a) substituting the `IRgbDeviceBackend` and `IAudioCaptureService`
implementations at the existing DI seams, and (b) *recording*/*rendering* their output. The
peripheral colors and the audio-reactive brightness are computed by the real code; the simulator
never recomputes them. Canvas scaling (10.2) is the only visual adaptation.

### The RGB tap point — record `Apply()`, don't recompute
[Source: `src/Engine/Devices/RgbNetAmbientDeviceService.cs:260-342`, `IRgbDeviceBackend.cs:10-23`]
- The push timer (`PushLatestFrame`, `:270-342`) fires every `UpdateIntervalMs` (33 ms / ~30 Hz,
  `:20`). For each device it computes `audioFactor = AudioModulation.BrightnessFactor(frame.Audio?.
  Intensity ?? 0f, audioDepth)` (`:306-308`), an `effective` brightness folding in placement +
  per-device + audio (`:314-318`), then calls
  `LedProjection.Project(device.NormalizedLeds, frame.Edges, effective, placement?.Anchor,
  placement?.Flip ?? false)` (`:322-324`) and finally `backend.Apply(push)` (`:327`).
- **So the tap point is `IRgbDeviceBackend.Apply(IReadOnlyList<RgbDeviceColors>)`**
  (`IRgbDeviceBackend.cs:19-23`). `RgbDeviceColors = { string DeviceId; int[][] Colors }`
  (`IRgbDeviceBackend.cs:97-103`) — `Colors[ledIndex] = [r,g,b]` sRGB 0-255, same order as that
  device's `NormalizedLeds`. The `VisualizationBackend` just stores the latest list; everything that
  produced those colors is the real service + real `LedProjection`.
- Model the recorder on the test fake: `FakeBackend` at
  `tests/Engine.Tests/Devices/RgbNetAmbientDeviceServiceTests.cs:408-439` already does exactly this —
  `Apply` appends under a lock, `Connect` returns a canned `RgbBackendConnection`, `Dispose`
  increments a counter. `VisualizationBackend` is that, plus a `LatestColors` snapshot + change
  notification for the WPF renderer. Recording must be thread-safe: the push timer runs on the
  threadpool (`RgbNetAmbientDeviceService.cs:205-207`).

### The backend factory seam — already injectable
[Source: `src/Engine/App.xaml.cs:184-189`, `RgbNetAmbientDeviceService.cs:24,50-56,173-182`]
- Production registers `IAmbientDeviceService` with a factory lambda
  `providers => new RgbNetBackend(logger, providers)` (`App.xaml.cs:187-189`). The service stores
  this as `Func<IReadOnlyCollection<string>, IRgbDeviceBackend> _backendFactory` (`:24`) and calls it
  in `ConnectCore` (`:181`). The simulator supplies
  `providers => new VisualizationBackend(...)` instead — **no service change**. This is the same
  pattern 10.1 uses for the capture/monitor seams.

### Device set — mirror `SIM_DEVICES`
[Source: `web/src/shared/simulator.ts:27-31`]
- `SIM_DEVICES` = keyboard `K95 RGB Platinum (sim)` 108 LEDs (`Keyboard`), mouse
  `Dark Core RGB Pro (sim)` 4 LEDs (`Mouse`), light strip `LS100 Light Strip (sim)` 27 LEDs
  (`LedStripe`). Reproduce these as `RgbBackendDevice`s (`IRgbDeviceBackend.cs:84-94`) with stable
  ids and generated `NormalizedLeds` 0..1 layouts (keyboard grid, mouse cluster, strip line) so the
  anchors read sensibly. **Reuse the *idea*, not the file** — `simulator.ts` is a TS browser fake
  (epic guardrail: "Leave `web/src/shared/simulator.ts` alone"); port the C# device list into the
  simulator code.

### Placement anchors — what the renderer must visualize
[Source: `src/Engine/Models/DevicePlacement.cs:9-55`, `LedProjection.cs:80-171`]
- `DevicePlacement = { string Anchor; bool Flip; float Brightness; bool Enabled }`
  (`DevicePlacement.cs:9-34`); anchors are `auto/left/right/above/below/behind/surround`
  (`DeviceAnchors`, `:41-55`). `LedProjection.Project` dispatch (`LedProjection.cs:97-105`):
  single-edge anchors feed every LED from one edge indexed by its along-edge position (`:99-102`),
  `surround` walks the perimeter by LED angle (`SampleSurround`, `:138-171`), `auto`/`behind`/unknown
  use nearest-edge (`SampleNearestEdge`, `:111-131`). `Flip` reverses zone/winding direction for
  single-edge + surround, ignored for auto/behind (`:78-79,99-102,142-145`). The renderer should
  position each device cluster *around* the source monitor per anchor so a viewer can confirm, e.g.,
  a `left`-anchored strip glows with the source's left edge and a flipped strip runs reversed — the
  whole point of validating placement without hardware.
- Per-device brightness/enabled already fold into the colors before `Apply` (excluded devices go to
  brightness 0 = dark, `RgbNetAmbientDeviceService.cs:314-318`), so the renderer needs no extra logic
  for those — they fall out of the recorded colors.

### Audio seam — synthetic source, real consumer
[Source: `src/Engine/Capture/IAudioCaptureService.cs:8-34`, `AudioCaptureService.cs:456-471`,
`DataProcessingService.cs:278-296,423`]
- `IAudioCaptureService` (`:8-22`): `IsCapturing`, `int BandCount {get;set;}`, `Start()`/`Stop()`,
  `event EventHandler<AudioAnalysisEventArgs>? AudioAnalyzed` (`:19`), `event ... Error`.
  `AudioAnalysisEventArgs` (`:24-34`): `float[] Bands` (length == `BandCount`, 0..1, low→high),
  `float Intensity` (0..1), `double TimestampMs` (monotonic). The real impl raises at ~30–60 Hz
  (`RaiseAudioAnalyzed`, `AudioCaptureService.cs:456-471` — note the monotonic `SharedClock`).
- Consumer is unchanged: `DataProcessingService.OnAudioAnalyzed` copies `e.Bands` + `Intensity` into
  `_latestBands`/`_latestIntensity` (`:278-296`); `BuildFrame` shapes them via `_shaper.Shape`
  (`:423`) into `FramePayload.Audio` (`:432`). That payload then feeds both audio-reactive effects
  (web side) and the peripheral `AudioModulation` factor (`RgbNetAmbientDeviceService.cs:306-308`).
  So a drop-in `SimulatedAudioCaptureService` exercises the *entire* real audio path with no engine
  change.
- **124 bpm pattern to port** [Source: `web/src/shared/simulator.ts:96-129`]: `makeSimFrame` builds
  `beatPhase = (ts * 124/60) % 1`, `kick = max(0, 1 - beatPhase*4)^1.5`, and per-band
  `bassBoost + melody + sparkle` clamped 0..1, with `intensity = min(1, mean(bands) + kick*0.35)`.
  Port the audio portion (bands + intensity) to C#; the edge-color portion of `makeSimFrame` is the
  10.1 capture concern, not this story. The browser simulator emits at `1000/60` ms
  (`simulator.ts:194-197`) — match that cadence ballpark.

### Premium gating — activate sim-Premium, don't touch the gate
[Source: `src/Engine/Services/EngineCoordinator.cs:279-307`, `Licensing/Entitlements.cs:26-27`,
`Licensing/LicenseValidator.cs:138-163`, `web/src/shared/simulator.ts:74-79,136`]
- `ApplyAmbientDeviceState` only starts the device service when
  `_settings.IsEnabled && _settings.AmbientDevicesEnabled && Entitlements.RgbPeripherals(_license.
  Current.IsPremium)` (`EngineCoordinator.cs:289-290`) and a source resolves (`:305-307`).
  `Entitlements.RgbPeripherals(bool premium) => premium` (`Entitlements.cs:27`) — RGB is Premium-only.
- So the simulator must run under an `IsPremium` entitlement, or the RGB path never starts and there
  is nothing to visualize. `LicenseInfo.IsPremium => IsValid && Edition == "premium"`
  (`LicenseValidator.cs:152`); `LicenseInfo.Free` is the default (`:154`). The browser simulator
  fakes this by setting `licenseKey = 'AFX1.sim.premium'` on `?premium=1` (`simulator.ts:136`) and a
  `simLicense` that treats any non-empty key as Premium (`simulator.ts:74-79`).
- Prefer activating sim-Premium through the existing `ILicenseService`/settings path in simulator
  startup so `_license.Current.IsPremium` is true at the seam the real coordinator reads — **leave
  `Entitlements` and `LicenseService` unmodified** (AC4/AC5). The dev agent should pick the least
  invasive mechanism (a sim-only `ILicenseService` shim returning a Premium `LicenseInfo`, or an
  already-minted dev key) and document it; either way the real gate code is untouched and the signed
  build is unaffected.

### Testing
- xUnit is the workhorse (no hardware, no WASAPI in CI), same discipline as the Epic 8 tests:
  - `VisualizationBackend`: drive a **real** `RgbNetAmbientDeviceService` wired to a
    `VisualizationBackend` factory (exactly as the simulator does), `SetPlacements` a known map,
    `SubmitFrame` a known `FramePayload`, `Start`, then poll until a push lands and assert the
    recorded `Apply()` colors equal `LedProjection.Project(device.NormalizedLeds, frame.Edges,
    effective, anchor, flip)` computed directly. This both proves the tap is faithful and re-asserts
    the fidelity invariant. Use the existing `WaitUntil` poll helper pattern
    (`RgbNetAmbientDeviceServiceTests.cs:76-88`) — no fixed sleeps.
  - `SimulatedAudioCaptureService`: subscribe to `AudioAnalyzed`, run for a window, assert event
    count implies ≈30–60 Hz, `Bands.Length == BandCount`, and all band/intensity samples ∈ [0,1] for
    both the 124 bpm pattern and the sine sweep; assert `IsCapturing` toggles with `Start`/`Stop` and
    nothing is raised after `Stop`.
  - Range smoke on the ported generator + `AudioModulation.BrightnessFactor` (already pure and
    unit-tested for clamping, `AudioModulation.cs:16-21`).
- No new bridge plumbing, so no new Vitest is required; just keep the existing Vitest + xUnit suites
  green. There is no on-hardware verification in this story — being hardware-free and sound-free is
  the point.

### Out of scope
- **Real RGB.NET / iCUE and real WASAPI.** The simulated backend never loads native SDK bits and the
  simulated audio source never touches WASAPI — this is deliberate (hardware-free, sound-free). Real
  on-hardware RGB and real system-audio fidelity remain owner verification on the actual machine
  (Story 8.1 AC10 already covers the hardware pass).
- **New peripheral/audio engine behavior.** This story validates the existing `LedProjection` /
  `AudioModulation` / device-service logic; it does not change projection, modulation, anchors, or
  the device service. Any behavior bug found is filed separately, not fixed here.
- **Bridge / settings contract changes.** No new C#/TS bridge types or settings keys; if any payload
  must change it is mirrored in `src/Engine/Bridge/` per the standing Epic 7/8 guardrail (not
  expected here).
- **The topology editor / scenario library / per-device placement editing UI** beyond the minimal
  controls needed to flip anchors for visual verification — the full editor is Story 10.5.
- **Automated snapshot/golden-image regression** of the peripheral viz — the headless render hook is
  Story 10.5; full CI golden images are out of scope for the epic.
