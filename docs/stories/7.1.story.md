# Story 7.1: Effect Library Expansion

## Status
Ready for Review

## Story
**As a** user who wants visual variety on my ambient monitors,
**I want** a much larger library of effects to choose from,
**so that** I can match the mood of whatever I'm doing and not get bored of the same five.

## Acceptance Criteria
1. At least **6 new effects** are added, bringing the gallery to ~11 total. Suggested set:
   `nebula` (domain-warped color clouds), `fire` (bass-reactive rising embers), `rain`
   (falling streaks tinted by screen color), `waveform` (audio oscilloscope line),
   `kaleidoscope` (symmetric color-driven mandala), `ripple` (water ripples pulsed by audio peaks).
   Final names/IDs may be adjusted by the dev, but the count and quality bar hold.
2. Each new effect is a **self-contained module** under `web/src/effects/<id>/` exposing the
   standard `EffectModule` (id, name, description, params, `create()`), with **no changes to the
   engine** required to add it (NFR8).
3. Every new effect appears in the control-window **gallery** with a live preview and in the
   **tray** preset/effect list, and can be selected per-monitor like the existing effects.
4. Each new effect is **screen-color reactive** (consumes `FramePayload` edge-zone colors) and
   **audio reactive** (consumes the audio bands) where it makes sense, and respects the global
   `intensity` and `brightness` settings via `setGlobals`.
5. Each new effect exposes a sensible set of tunable `params` (using the controls available after
   Story 7.2 if that lands first; otherwise plain range/select/toggle).
6. The registry/manifest sync test passes and param-hygiene checks pass
   (`web/src/effects/registry.test.ts`): unique IDs, unique param keys, defaults on every param.
7. Performance: each effect holds the configured `MaxFps` cap on the dev 3×1080p rig without
   stutter; gallery previews run at the reduced preview quality (`ctx.preview === true`).
8. No GPU-context leaks: switching effects repeatedly does not exhaust WebGL contexts (each
   `dispose()` releases its renderer/forces context loss, as the existing effects do).

## Dev Notes

### Effect module contract (the only thing you must conform to)
[Source: `web/src/effects/types.ts`]
- `EffectModule`: `{ id, name, description, params: ParamDef[], create(ctx): EffectInstance }`.
- `EffectInstance`: `onFrame(frame)`, `render(timeMs, dtMs)`, `setParams(params)`,
  `setGlobals(globals)`, `resize(w,h)`, `dispose()`.
- `ParamDef.type` is `'range' | 'select' | 'toggle'` today; the control UI auto-generates controls
  from these. (Story 7.2 may add `color`/`palette` types — coordinate if both are in flight.)
- `GlobalRenderSettings`: `{ intensity: 0..1, brightness: 0..1 }` — every effect must honor these.

### Reference implementation (copy its shape)
[Source: `web/src/effects/plasma/index.ts:58-256`]
- DEFAULTS object → param array; a class implementing `EffectInstance`; Three.js renderer +
  ShaderMaterial with uniforms; `onFrame` extracts audio bands + palette targets (no rendering);
  `render` eases uniforms then draws; `setParams` clamps; `dispose` releases resources and forces
  GL context loss. `shaders.ts` exports `VERTEX_SHADER` / `FRAGMENT_SHADER` strings.

### Registration + manifest sync (don't skip)
[Source: `web/src/effects/registry.ts:1-20`, `web/src/effects/manifest.json`, `registry.test.ts`]
- `registry.ts` is the TS source of truth; `manifest.json` mirrors id/name/description for non-TS
  consumers; `registry.test.ts` asserts they match field-for-field and enforces param hygiene
  (lines ~18-21 match; ~44-99 hygiene). It currently asserts **exactly 5 effects** (line ~13) —
  bump that expectation.

### Data contracts (already provided by the engine — do not change)
[Source: `web/src/shared/bridge.ts`]
- `FramePayload` carries edge-zone colors + audio bands per frame; `EffectParams` is an opaque
  `Record<string, number|string|boolean>` the engine round-trips and persists in
  `ApplicationSettings.EffectParamsById`. New effects consume these; they don't add to the bridge.

### Gallery & previews
[Source: `web/src/control/components/EffectGallery.tsx:18-138`]
- Previews are lazy, ~30fps, paused off-screen, disposed on unmount, and created with
  `{ canvas, windowConfig: null, preview: true }`. Keep `preview === true` paths cheap.

### Testing
- Framework: Vitest (`web/`). Keep `registry.test.ts` green; add per-effect smoke tests.
- The C# side needs no changes for this story.

### Project Structure Notes
New effects live entirely in `web/`. No `src/Engine/` changes. Build output flows to
`src/Engine/wwwroot` via the existing Vite `outDir` — packaging (Story 7.4) picks them up for free.
