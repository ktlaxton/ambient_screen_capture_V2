# Story 7.4: Distributable Signed Installer + Auto-Update

## Status
Ready for Review (AC5 signing gated on owner certificate; clean-machine + update-cycle verification outstanding)

## Story
**As a** user (and as the owner shipping this),
**I want** AmbientFx packaged as a real installer I can double-click to install and run as a normal
app, that's code-signed and updates itself,
**so that** I don't need a dev toolchain to run it, Windows doesn't scream about an unknown
publisher, and I get fixes/new effects automatically.

## Scope decision (owner-confirmed 2026-06-11)
Full Phase-5 packaging: **installer + code signing + auto-update**. Recommended tooling: **Velopack**
(modern Squirrel successor) for a self-contained installer plus delta auto-update in one tool. This
supersedes the deferral noted in the rebuild memory; MSIX Store submission remains out of scope.

## Acceptance Criteria
1. A **single build command** (e.g. an npm script or a `build.ps1`) produces a distributable: it
   builds `web/` → `wwwroot`, then `dotnet publish` the engine, then packs the installer. No manual
   copy steps.
2. The output is a **self-contained** app (bundles the .NET 8 runtime; the user does **not** need
   .NET installed). Target `win-x64`, matching the project's existing platform.
3. The **WebView2 runtime dependency** is handled: installer checks for / bootstraps the Evergreen
   WebView2 runtime (or the app shows the existing "runtime missing" guidance). The app must launch
   on a clean Windows 11 machine with no dev tools.
4. A user can **double-click the installer**, it installs to a per-user location with a Start-menu
   shortcut and an entry in "Apps & features" (uninstallable), and launching runs AmbientFx
   normally (tray + control window, effects work).
5. The app and installer are **code-signed** with the owner's certificate; SmartScreen does not
   flag an unknown publisher (reputation builds over time, but the signature is valid).
6. **Auto-update** works: on launch the app checks an update feed, downloads updates in the
   background, and applies them on next start (Velopack delta updates). A manual "Check for updates"
   action is available. Update feed location is configurable (GitHub Releases or a static URL).
7. **Single-instance + lifecycle still hold** post-package: installed exe respects the mutex, and
   Quit fully terminates (depends on Story 7.3). Autostart (existing `AutostartService`) points at
   the installed exe path, not a Debug build path.
8. Versioning: the build stamps a semantic version into the assembly and the Velopack release so
   updates are ordered correctly. A documented release process exists (how to cut a new version).

## Dev Notes

### Build/bundle wiring that already exists (build on it)
[Source: `web/vite.config.ts:11`, `src/Engine/AmbientFx.csproj:18`]
- Vite `outDir` already targets `../src/Engine/wwwroot`; the csproj copies `wwwroot\**` to output
  with `CopyToOutputDirectory="PreserveNewest"`. So `npm run build` then `dotnet publish` yields a
  self-contained app with the web assets embedded — the pipeline just needs to chain these.

### Project config to extend
[Source: `src/Engine/AmbientFx.csproj:5-24`]
- TFM `net8.0-windows10.0.22621.0`, min OS `10.0.19041.0`, `PlatformTarget=x64`, WPF + WinForms,
  WebView2 `1.0.3967.48`. `PublishSingleFile`/`SelfContained` are **not** set — add a publish
  profile or pass flags. Add `<RuntimeIdentifier>win-x64</RuntimeIdentifier>` and a version
  property (`<Version>`) for stamping.

### WebView2 serving is path-relative (safe to relocate)
[Source: `src/Engine/Hosting/WebViewHelpers.cs:23,47-49`]
- `WebRootPath = AppContext.BaseDirectory/wwwroot`; virtual host `ambientfx.example` mapped to that
  folder. Because it's relative to the install dir, packaging/relocation needs no URL changes.

### Lifecycle must survive packaging
[Source: `src/Engine/App.xaml.cs:22-51`, Story 7.3]
- Single-instance mutex `AmbientFx_SingleInstance_B6E3`; Velopack's `VelopackApp...Run()` must come
  **before** the single-instance check and DI so install/update/uninstall hooks short-circuit
  cleanly. Confirm Quit (Story 7.3) terminates the installed process fully.

### Autostart
[Source: `src/Engine/Services/AutostartService.cs`]
- Re-point autostart registration at the installed executable path after packaging; Velopack exposes
  the installed exe path. A Debug-path autostart entry would break post-install.

### External dependency / blocker
- **Code-signing certificate** must be provided by the owner (OV/EV code-signing cert). Until then,
  steps 1–4 and 6 can proceed unsigned for testing; AC5 is gated on the cert. Flag this in the
  handoff so it doesn't silently block.

### Why Velopack over MSIX (rationale for the dev)
- Velopack = installer + delta auto-update + signing in one, no Store account, simplest path to the
  owner's "double-click to install, updates itself" ask. MSIX/Store is heavier and out of scope.
  (Memory notes Velopack/Squirrel were the originally-intended Phase-5 tooling.)

### Testing
- Primary verification is manual on a clean machine/VM (AC 2-7). Add a CI/build smoke step that runs
  the full build script and asserts the installer artifact is produced.
